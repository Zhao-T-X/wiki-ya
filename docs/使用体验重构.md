# 使用体验重构（UX Refactor）

> 目标：把 wiki-ya 从「功能验证系统」变成「每天真的会用」的知识工具。
> 原则：**只重做"用户怎么用"，不重写技术架构**；先改前端，再据此决定后端接口。

---

## 1. 现状诊断（已核对代码）

| 现象 | 证据 |
|---|---|
| 首页 = 10 个平级模块，用户要自己决定"去哪" | `components/Sidebar.tsx:34-52`：Inbox / Knowledge / Search / Review / Ask / Research / Graph / Timeline / Migration / Settings |
| Inbox 只是"表单 + 最近文档"，不是入口 | `features/inbox/InboxPage.tsx` |
| 捕获后的反馈是技术指标，不是产品语言 | `InboxPage.tsx:167`「生成 N 个片段」 |
| 反馈文案已过期（说 AI 未启用） | `InboxPage.tsx:171`「AI 抽取尚未启用（Phase 6）」——实际早已实现 |
| 冲突/待办必须"进 Review 页面"才看得到 | `features/review/ReviewPage.tsx` |

一句话：**能力都做在页面里，状态没有推给用户。**

---

## 2. 目标信息架构

```text
┌─────────────────────┐
│ wiki-ya             │
│                     │
│ + Capture           │  ← 主入口，最显眼
│                     │
│ Home                │  ← 捕获 + 待办 + 最近
│ Knowledge           │  ← Current / History / Related
│ Review              │  ← 系统待办（不是"功能页"）
│ Search              │  ← Search + Ask 合一
│                     │
│ ───────────────     │
│ More                │  ← 折叠：Ask / Research / Graph / Timeline / Migration
│ Settings            │
└─────────────────────┘
```

**用户只需记住两个动作**：*我要记东西* → Capture；*我要找东西* → Search。

---

## 3. 六项改造（文件级映射）

### ① Home 成为唯一入口
- **改**：`app/router.tsx`（`/` → `/home`，`/inbox` 重定向保留兼容）、`components/Sidebar.tsx`（10 → 5 + 折叠 More）、`stores/ui.ts`（`ModuleId: inbox → home`）、**新增** `features/home/HomePage.tsx`
- **复用 IPC**：`create_document` / `list_documents` / `list_review_items` / `knowledge_health`
- **不需要改 Rust**
- **验收**：打开应用第一眼就是捕获框，不需要先选模块。

### ② 捕获后立刻给反馈（"到底发生了什么"）
- **改**：`HomePage` 的**结果面板**
- 反馈内容（全部用真实数据，不编造）：
  ```
  ✓ 已保存  ✓ 已切分 12 个片段
  下一步：[用 AI 抽取知识] [运行演化分析] [查看文档]
  ```
- **复用 IPC**：`DocumentSummary.chunkCount/charCount`、`extract_claims`、`analyze_document`
- **产品决策已定**：捕获后**自动抽取**（AI 已启用时）。只产生**候选**，逐条确认后才落库，
  因此不会污染知识库；未配置 Key 时行为不变（不调用 AI）。
- **验收**：捕获后 30 秒内知道"系统处理了什么、下一步是什么"。

### ③ Knowledge Detail 成为最可信页面
- **改**：`features/knowledge/ClaimDetailPage.tsx`（重组为 What / Why current / Evidence / History / Related）
- **新增**"为什么是当前"说明：由 **已有字段** 组合，无需后端改动：
  - `lifecycle === 'current'` → 当前知识
  - `relations` 中存在 `accepted supersedes` 指向它 → 「被 X 取代了旧知识」
  - `evidence.length` → 「N 个来源支持」
- **验收**：打开一条知识，10 秒内能回答"它为什么是真的、以前是什么"。

### ④ Review 变成"系统待办"
- **改**：`HomePage` 增加「需要你处理」区块（`list_review_items` 前 N 条 + 直接决策入口）；`ReviewPage` 保留为完整列表
- **验收**：不在 Home 也能察觉待办；Review 不再是"要主动去的页面"。

### ⑤ Search 与 Ask 合一
- **改**：`features/search/SearchPage.tsx`（一个输入框，先给 Knowledge 结果，提供「用 AI 回答」动作，复用 `ask`）
- **排序调整**：Knowledge > Evidence > Document（现在是按分数混排）
- **不需要改 Rust**（两个 IPC 都已存在）
- **验收**：用户不需要判断"该搜索还是该问 AI"。

### ⑥ 内部复杂性收进 Advanced
- **改**：`features/ask/AskPage.tsx`（Context Stats 默认折叠）、`features/settings/SettingsPage.tsx`（Embedding / Base URL / Budget 收进 Advanced）
- **验收**：默认界面不出现 predicate / RRF / token budget / embedding 等词。

## 4. 实现状态

| 项 | 状态 | 落点 |
|---|---|---|
| ① Home 成为唯一入口 | **已实现** | `components/Sidebar.tsx`、`features/home/HomePage.tsx`、`app/router.tsx`、`stores/ui.ts` |
| ② 捕获后立刻给反馈 | **已实现** | `HomePage` 结果面板（已保存 / 切分 / 用 AI 抽取 / 检查知识变化 / 查看文档） |
| ③ Knowledge Detail 重构 | **已实现** | `features/knowledge/ClaimDetailPage.tsx`（What / Why current / Evidence / History / Related + 技术细节折叠） |
| ④ Review 待办化 | **已实现** | `Sidebar` 常驻待办计数；`ReviewPage` 队列语义 + 处理反馈 |
| ⑤ Search 与 Ask 合一 | **已实现** | `features/search/SearchPage.tsx`（单输入框、知识优先、AI 回答一键可达、高级折叠） |
| ⑥ 内部复杂性收进 Advanced | **已实现** | `SearchPage`（kind / 语义 / 上下文统计）、`SettingsPage`（接口基址 / 向量模型 / 预算 / 受控词表） |

- **全程未改动任何 Rust 代码**（符合"先改前端"）。
- `/ask` 路由保留（深链不失效），但已从导航移除——提问能力并入 Search。
- 旧 `/inbox` 路径永久重定向到 `/home`，历史链接不失效。

### 待办（未做）
- Context 遥测的 History / Trace 回放 UI（后端已落库，仅缺前端视图）。
- Knowledge 列表尚未按 lifecycle 做「当前 / 历史」分组（当前靠标签区分）。

## 5. 后续可能需要后端配合的点（仅记录，未实施）

| 需求 | 现状 | 是否必须改 Rust |
|---|---|---|
| Home 显示"今天新增 N 条知识" | `knowledge_health` 只有总量，无增量/时间窗 | 若要"今天"需加时间过滤 |
| Knowledge 列表默认只显示 Current | `list_claims` 支持 `status` 过滤但不支持按 Resolver 语义过滤 | 若要在 SQL 层过滤需后端支持 |
| Search 结果按 Knowledge 优先 | 后端已按 RRF 融合，前端可本地重排 | 否（前端可做） |

> 结论：**先不改 Rust**。等 ③④⑤⑥ 的交互定下来，再回来看哪些真的需要后端新接口。
